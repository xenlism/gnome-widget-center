# GWC Repo Maker

แอป GTK4 + libadwaita (GJS) สำหรับ **สร้างและดูแลคลังวิดเจ็ต (store repository) ของ GNOME Widget Center**
เพิ่มวิดเจ็ตและชุดธีมจากโฟลเดอร์ในเครื่อง เซ็นลายเซ็น สร้างไซต์ แล้วเผยแพร่ผ่าน GitHub Pages ได้จากหน้าจอเดียว

> English: [README.md](README.md)

แอปนี้เป็นโปรเจกต์แยกจากตัว extension และจากเทมเพลตคลัง `gwc-store` ต้องการแค่โฟลเดอร์ `tools/` ของคลัง ซึ่งแนบมาแล้วใน `backend/tools`

## ทำอะไรได้บ้าง
- **สร้าง / เปิดคลัง** เลือกโฟลเดอร์ด้วยปุ่ม Browse… (จำคลังที่เปิดล่าสุดไว้) คลังใหม่จะได้เครื่องมือ build, workflow ของ CI และกุญแจเซ็นให้ทันที
- **ต้นทาง (Sources)** เลือกโฟลเดอร์ที่มีวิดเจ็ตและชุดธีม (โฟลเดอร์ extension ที่มี `widgets/` กับ `themepacks/` หรือจะเลือกโฟลเดอร์ใดโฟลเดอร์หนึ่งก็ได้) แอปแสดงรายการที่พบ ติดป้าย *ใหม่* / *มีในคลังแล้ว* / *ไม่ถูกต้อง* แล้วนำเข้าเฉพาะที่ติ๊กเลือก ทุกรายการผ่านการตรวจชุดเดียวกับตอน build
- **กุญแจเซ็น** สร้าง นำเข้า คัดลอก บันทึกกุญแจสาธารณะ สำรองกุญแจส่วนตัว (ใช้ได้โดยไม่ต้องเปิดคลัง)
- **ผู้เขียนและการเพิกถอน** กำหนดว่าใครเซ็นวิดเจ็ตได้ และถอนเวอร์ชันที่มีปัญหา
- **ตั้งค่าคลัง** ชื่อ URL มิเรอร์ ชนิดคลัง นโยบายลายเซ็น
- **Build และเผยแพร่** บิลด์พร้อมล็อกสด ตรวจผล และมีขั้นตอน push ขึ้น GitHub Pages
- หน้าจอเป็นภาษาไทยหรืออังกฤษตาม locale (บังคับได้ด้วย `GWC_LANG=th|en`)

## วิธีติดตั้ง

### สิ่งที่ต้องมี
| ส่วน | เวอร์ชัน | ใช้ทำอะไร |
| --- | --- | --- |
| gjs | ≥ 1.76 | รันตัวแอป |
| GTK | ≥ 4.10 | หน้าจอ |
| libadwaita | ≥ 1.5 | หน้าจอ |
| python3 | 3.9 ขึ้นไป | รันเครื่องมือ build/เซ็น |
| python `cryptography` | – | สร้างและเซ็นด้วยกุญแจ Ed25519 (จำเป็น) |
| python `Pillow` | – | สร้างภาพ cover อัตโนมัติ (ไม่บังคับ) |
| git | – | ให้แอปรัน `git init` ตอนสร้างคลัง (ไม่บังคับ) |

### Arch Linux
```sh
sudo pacman -S --needed python python-cryptography python-pillow gjs gtk4 libadwaita git
./install.sh
```

### Debian / Ubuntu
```sh
sudo apt install gjs gir1.2-gtk-4.0 gir1.2-adw-1 python3 python3-cryptography python3-pil git
./install.sh
```

### Fedora
```sh
sudo dnf install gjs gtk4 libadwaita python3 python3-cryptography python3-pillow git
./install.sh
```

### ติดตั้งสคริปต์
`./install.sh` ทำให้ตามลำดับนี้
1. ตรวจว่ามี `cryptography` หรือยัง ถ้าไม่มีจะสร้าง virtualenv ที่ `.venv` ในโฟลเดอร์แอปแล้วติดตั้งไลบรารีลงไป (ไม่ใช้ pip ของระบบ จึงไม่ติด error `externally-managed-environment`) แอปจะใช้ `.venv` นี้เองอัตโนมัติ
2. ถ้าสร้าง venv ไม่ได้ จะแสดงคำสั่งติดตั้งผ่าน package manager ให้แทน
3. สร้างตัวเรียก `~/.local/bin/gwc-repo-maker` และไฟล์ desktop entry ใน `~/.local/share/applications`

> `gjs`, GTK และ libadwaita เป็นแพ็กเกจของระบบ สคริปต์ไม่ติดตั้งให้ ต้องลงด้วย package manager ตามด้านบน
> ถ้า `~/.local/bin` ไม่อยู่ใน `PATH` ให้เพิ่มเอง หรือรันด้วย `bin/gwc-repo-maker` ตรง ๆ

### ไม่ติดตั้งก็ใช้ได้
```sh
bin/gwc-repo-maker                 # เปิดแอป
bin/gwc-repo-maker --repo ~/my-store   # เปิดคลังนี้ทันที
```

## วิธีใช้งาน

### 1) สร้างคลังใหม่
หน้าแรก → **สร้างคลังใหม่** แล้วกรอก
- **ชื่อคลัง** และ **รหัสคลัง** (a-z 0-9 -)
- **URL สาธารณะ** ต้องขึ้นต้น `https://` และลงท้าย `/` เช่น `https://USER.github.io/my-widget-store/`
- **ชนิด** `official` หรือ `community` (community บังคับลายเซ็นผู้เขียนทุกวิดเจ็ต)
- **รหัสกุญแจเซ็น** ปุ่ม *แนะนำ* ให้รหัสที่ยังไม่ซ้ำ แอปจะสร้างกุญแจใหม่ให้ตามรหัสนี้
- **สร้างไว้ในโฟลเดอร์** ปุ่ม *เลือก…* (Browse…)

เสร็จแล้วแอปแสดง **ลายนิ้วมือ (fingerprint)** ของกุญแจ ให้ส่งค่านี้ให้ผู้ใช้ที่จะเพิ่มคลังของคุณ และ **สำรองไฟล์กุญแจส่วนตัวไว้**

### 2) เพิ่มวิดเจ็ตและชุดธีม
- **นำเข้าจากโฟลเดอร์:** หน้า **ต้นทาง** → *Browse…* → เลือกโฟลเดอร์ → ติ๊กรายการ → *Import selected*
- **สร้างวิดเจ็ตใหม่:** หน้า **วิดเจ็ต** → *วิดเจ็ตใหม่* ได้ metadata, `widget.js` เริ่มต้น, config และ cover
- **นำเข้าไฟล์เดียว:** หน้า **วิดเจ็ต** → *นำเข้า…* (`.gwcw` หรือโฟลเดอร์) / หน้า **ชุดธีม** → *นำเข้า…* (`.gwct`)

**วิดเจ็ตขนาดใหญ่:** วิดเจ็ตที่ zip เกิน 4 MiB (หรือแตกแล้วเกิน 16 MiB) จะถูก build เป็นแพ็กเกจ *เวอร์ชัน 2* อัตโนมัติ คือไฟล์ `.gwcw` เล็ก ๆ กับ zip ดิบ `.gwcp` (zip ได้ถึง 64 MiB แตกแล้วถึง 128 MiB) ไม่ต้องตั้งค่าอะไร ปุ่ม **เผยแพร่** อัปโหลดให้ทั้งสองไฟล์ การอัปโหลดไฟล์ใหญ่ใช้เวลานาน และไซต์ GitHub Pages มีขีดจำกัดขนาดรวม จึงควรลดขนาดไฟล์หนัก ๆ ผู้ใช้ต้องใช้ Widget Center รุ่นปัจจุบันเพื่อติดตั้งวิดเจ็ตเวอร์ชัน 2 รุ่นเก่าจะแจ้งข้อความชัดเจนเฉพาะวิดเจ็ตนั้น

แอปเทียบสิทธิ์ที่วิดเจ็ตประกาศกับที่โค้ดใช้จริง ถ้าไม่ตรงจะขึ้นเป็นข้อผิดพลาดในหน้า **ภาพรวม**

### 3) เซ็นในนามผู้เขียน (ถ้าต้องใช้)
ปุ่มรูปเครื่องหมายถูกที่แถววิดเจ็ต → เลือกกุญแจผู้เขียน ถ้ายังไม่มีกุญแจจะมีปุ่ม **สร้างกุญแจ** ให้ ลายเซ็นผูกกับเนื้อหา เวอร์ชัน ไฟล์หลัก และสิทธิ์ ณ ตอนนั้น แก้ไขภายหลังต้องเซ็นใหม่

### 4) เพิ่มผู้เขียน
หน้า **ผู้เขียน/เพิกถอน** → *เพิ่มผู้เขียน…* ในช่องกุญแจสาธารณะ
- *เลือก…* เลือกไฟล์ `.pub.json` (หรือไฟล์ที่มีกุญแจ base64) แล้วเติม kid กับกุญแจให้
- *สร้างกุญแจ* สร้างกุญแจผู้เขียนใหม่ในเครื่องนี้แล้วเติมกุญแจสาธารณะให้ทันที

ช่อง "id ที่อนุญาต" คั่นด้วย `,` เช่น `me.clock, me.*`

### 5) ตั้งค่าและเพิกถอน
- **ตั้งค่า:** แก้แล้วกด *บันทึกการตั้งค่า* ค่าที่ไม่ถูกต้องจะถูกปฏิเสธและไม่มีอะไรเปลี่ยน
- **เพิกถอน:** ถอนเวอร์ชัน (ใส่ hash 32 ตัว) หรือทุกเวอร์ชัน (เว้น hash ว่าง) ผู้ใช้จะเห็นผลในการตรวจครั้งถัดไป อย่าลืมเผยแพร่หลังแก้

### 6) เผยแพร่ (ไม่ต้องใช้เทอร์มินัล git หรือ secret ของ GitHub)
หน้า **Build & publish** กลุ่ม **เผยแพร่ขึ้น GitHub**:
1. กด **ล็อกอินด้วย GitHub** ครั้งเดียว (แอปโชว์รหัสและคัดลอกให้ เปิด GitHub ในเบราว์เซอร์ แล้วกด *Authorize*) ถ้าแอปไม่มี client id ให้ใช้ **ใช้โทเคน…** แทน หน้า GitHub จะเปิดพร้อมติ๊กสิทธิ์ `public_repo` ไว้ให้
2. ตรวจ **ชื่อ repository** (ถ้ายังไม่มี จะสร้างเป็น public ให้)
3. กด **เผยแพร่** แอปจะตรวจ GitHub ตั้ง URL สาธารณะให้ตรงกับ Pages สร้าง **เซ็นในเครื่องนี้** ตรวจ อัปโหลดขึ้น branch `gh-pages` และเปิด GitHub Pages จากนั้นแสดงที่อยู่คลังกับลายนิ้วมือกุญแจที่ต้องส่งให้ผู้ใช้

**มีไซต์ GitHub Pages อยู่แล้ว?** ที่ *เผยแพร่ที่ไหน* เลือก *โฟลเดอร์ในไซต์ GitHub Pages ที่มีอยู่แล้ว* ใส่ repository ของไซต์ (`ชื่อ` หรือ `เจ้าของ/ชื่อ` เช่น `you.github.io`) และชื่อโฟลเดอร์ (เช่น `gwc-store`) คลังจะอยู่ที่ `https://you.github.io/gwc-store/` แอปอ่านว่าไซต์นั้นเผยแพร่จาก branch และโฟลเดอร์ไหน แล้ว commit เฉพาะในโฟลเดอร์ของคุณ ไม่แตะไฟล์อื่นหรือการตั้งค่า Pages จะปฏิเสธโฟลเดอร์ที่มีของที่ไม่ใช่คลังอยู่แล้ว และชื่อโฟลเดอร์ห้ามขึ้นต้นด้วย `.` หรือ `_` (GitHub Pages ข้ามโฟลเดอร์แบบนั้น) ถ้าไซต์ deploy ด้วย GitHub Actions ไฟล์จะถูก commit แต่จะออนไลน์ก็ต่อเมื่อ workflow นั้นเผยแพร่โฟลเดอร์นี้ แอปจะเตือน ถ้า branch ถูก protect จนไม่ยอมให้ commit แอปจะแจ้ง ไม่พยายามเลี่ยง

**โดเมนของคุณเอง** (GitHub แบบ repository ของคลังเอง): ใส่ช่อง *โดเมนของคุณเอง* เช่น `store.example.com` URL สาธารณะจะเป็น `https://store.example.com/` และแอปอัปโหลดไฟล์ `CNAME` ที่ GitHub Pages อ่าน ส่วน DNS (CNAME ไปที่ `you.github.io`) และการติ๊ก *Enforce HTTPS* ใน Settings > Pages ของ repository เป็นหน้าที่ของคุณ จนกว่า GitHub ตรวจโดเมนผ่าน ที่อยู่นั้นจะยังไม่ตอบ

**โฮสต์ของฉันเอง** (คลังส่วนตัว อินทราเน็ต Cloudflare Pages, Netlify, S3, nginx, NAS ฯลฯ): เลือกโหมดนี้แล้วใส่ที่อยู่สาธารณะ (`https://.../` ลงท้ายด้วย `/`) แอปจะตรวจว่าที่นั่นมีอะไรออนไลน์อยู่ build และเซ็นในเครื่องนี้ แล้วบอกโฟลเดอร์ที่ต้องอัปโหลด ไม่ใช้บัญชี GitHub ถ้ายังไม่มีอะไรออนไลน์ แอปจะถามว่านี่คือรุ่นแรกหรือไม่ (ตอบ "รุ่นแรก" ผิด จะทำให้เครื่องผู้ใช้ปฏิเสธอัปเดตของคุณ จึงถามแทนการเดา) และถ้าเข้าถึงที่อยู่ไม่ได้จะหยุดก่อน build รอบถัดไปต่อจากรุ่นที่ออนไลน์และเก็บรุ่นก่อนหน้าไว้ ใช้โหมดนี้กับทุกอย่างที่ไม่ควรอยู่บน GitHub แอปเซ็นคลังได้ไม่ว่าจะเปิดสาธารณะหรือไม่ แต่คลังต้องเข้าถึงผ่าน `https://` ได้โดยคนที่จะเพิ่มคลัง ไซต์ GitHub Pages เป็นสาธารณะแม้ repository จะเป็น private และการล็อกอินที่แอปใช้เข้าถึงได้เฉพาะ repository สาธารณะ จึงไม่เผยแพร่ไป repository แบบ private

**คลังชุมชนหรือคลังทางการ และชื่อ:** *ชนิดของคลัง* (ทางการ / ชุมชน) และชื่อคลังตั้งตอนสร้าง และแก้ได้ที่ *ตั้งค่า* รหัสคลัง (id) แก้ไม่ได้หลังสร้าง ส่วนชื่อ repository บน GitHub ชื่อโฟลเดอร์ และที่อยู่ ไม่ผูกกับรหัสคลัง ตั้งเป็นอะไรก็ได้

กุญแจเซ็นไม่ออกจากเครื่องนี้ เผยแพร่ซ้ำจะอัปโหลดเฉพาะที่เปลี่ยนและต่ออายุลายเซ็น คลังที่สร้างใหม่ตั้งอายุลายเซ็น 180 วัน (ไม่มี CI รายสัปดาห์คอยต่อให้) หน้านี้จะเตือนเมื่อเหลือน้อยกว่า 30 วัน แค่กด **เผยแพร่** อีกครั้ง

ซอร์สวิดเจ็ตอยู่ในเครื่องคุณ (สำรองโฟลเดอร์ไว้) บน GitHub มีแค่ไซต์ที่ build เสร็จแล้ว

โทเคน GitHub เก็บที่ `<โฟลเดอร์กุญแจ>/github.token` (สิทธิ์ 0600) กด **ออกจากระบบ** เพื่อลบ หรือเพิกถอนที่ github.com/settings/applications

ปุ่ม **ล็อกอินด้วย GitHub** ต้องมี OAuth App ที่เปิด *Device Flow* (GitHub → Settings → Developer settings → OAuth Apps) ใส่ client id ใน `backend/github_client_id.txt` หรือ `GWC_GH_CLIENT_ID` ถ้าไม่มีแอปจะใช้ฟอร์มโทเคนแทน

**ขั้นสูง** (พับอยู่ในหน้าเดียวกัน): build ตัวอย่าง build เซ็นเอง และ flow GitHub Actions ใช้วิธีเดียวต่อหนึ่ง repository อย่าใช้ทั้งสองอย่าง

## กุญแจเซ็น (Ed25519)
เมนู → **กุญแจเซ็น…** (หรือปุ่มในหน้าแรก ใช้ได้โดยไม่ต้องเปิดคลัง)

| ปุ่ม | ทำอะไร |
| --- | --- |
| สร้างกุญแจ… | สร้างกุญแจผู้เขียน หรือกุญแจเซ็นคลัง (เมื่อเปิดคลังอยู่) |
| นำเข้า… | เลือกไฟล์กุญแจส่วนตัว (`.key`) ที่มีอยู่แล้วเข้าโฟลเดอร์กุญแจ ไม่ทับกุญแจเดิม |
| คัดลอก / บันทึกกุญแจสาธารณะ | ส่งให้ผู้ดูแลคลังหรือใส่ใน `authors.json` |
| สำรองกุญแจส่วนตัว… | คัดลอกไฟล์กุญแจไปเก็บ (ออฟไลน์หรือเข้ารหัส) |
| เปิดโฟลเดอร์กุญแจ | `~/.config/gwc-repo-maker/keys` |

- กุญแจเป็น **Ed25519 ไม่ใช่ PGP/OpenPGP** เพราะ Widget Center ตรวจเฉพาะลายเซ็น Ed25519 จึงใช้กุญแจ PGP ไม่ได้
- กุญแจส่วนตัวคือ seed 32 ไบต์ เก็บสิทธิ์ `0600` และ **ไม่อยู่ในคลังเด็ดขาด** ใครมีไฟล์นี้เซ็นแทนคุณได้
- แชร์ได้เฉพาะกุญแจสาธารณะหรือลายนิ้วมือ

## ตัวแปรสภาพแวดล้อม
| ตัวแปร | ความหมาย |
| --- | --- |
| `GWC_LANG=th\|en` | บังคับภาษาหน้าจอ |
| `GWC_KEY_DIR` | เปลี่ยนโฟลเดอร์เก็บกุญแจ (ค่าเริ่มต้น `~/.config/gwc-repo-maker/keys`) |
| `GWC_PYTHON` | บังคับใช้ Python ตัวนี้ (ค่าเริ่มต้น `.venv/bin/python3` ถ้ามี ไม่งั้น `python3` ในระบบ) |
| `GWC_TOOLS` | ใช้โฟลเดอร์ `tools/` อื่นแทน `backend/tools` |

## แก้ปัญหา
| อาการ | วิธีแก้ |
| --- | --- |
| `externally-managed-environment` ตอนใช้ pip | รัน `./install.sh` (ใช้ venv) หรือติดตั้ง `python-cryptography` / `python3-cryptography` ผ่าน package manager |
| `ModuleNotFoundError: cryptography` | รัน `./install.sh` ใหม่ หรือดูข้อด้านบน |
| ไม่มีโมดูล venv (Debian/Ubuntu) | `sudo apt install python3-venv` |
| `Typelib ... Adw-1 not found` | ติดตั้ง `gir1.2-adw-1` (Debian/Ubuntu) หรือ `libadwaita` (Arch/Fedora) |
| คำสั่ง `gwc-repo-maker` ไม่พบ | เพิ่ม `~/.local/bin` ใน `PATH` หรือรัน `bin/gwc-repo-maker` |
| บิลด์เซ็นแจ้ง `No private key for '…'` | กุญแจเซ็นของคลังไม่มีในเครื่องนี้ ให้นำเข้าด้วยปุ่ม *นำเข้า…* ในหน้าต่างกุญแจเซ็น หรือใช้บิลด์ตัวอย่าง |
| ไอคอนบางตัวหาย | ระบบมีชุดไอคอนน้อย ไม่กระทบการทำงาน |

## ถอนการติดตั้ง
```sh
rm ~/.local/bin/gwc-repo-maker ~/.local/share/applications/io.github.xenlism.GwcRepoMaker.desktop
rm -rf .venv                               # ถ้าเคยให้ install.sh สร้างไว้
# กุญแจอยู่ที่ ~/.config/gwc-repo-maker/keys  (ลบเมื่อสำรองแล้วเท่านั้น!)
```

## สำหรับนักพัฒนา
ตรรกะทั้งหมดอยู่ใน Python (`backend/tools/gwc_repo.py` พิมพ์ผลเป็น JSON) ตัวแอปเป็นแค่หน้าจอครอบ

ให้ `backend/tools` ตรงกับ `gwc-store`:
```sh
./sync-backend.sh /path/to/gwc-store
```
คลังที่มี `tools/` ของตัวเองจะถูกจัดการด้วยสำเนานั้นเสมอ (เวอร์ชันเดียวกับ CI ของคลังนั้น)

เทสต์
```sh
# backend ภายใต้ GJS จริง
GWC_KEY_DIR=$(mktemp -d) gjs -m tests/backend.test.js
# UI: กดปุ่มจริงในหน้า Sources, ฟอร์ม (Browse / สร้างกุญแจ) และหน้าต่างกุญแจ (ต้องมีจอ: xvfb-run)
GWC_KEY_DIR=$(mktemp -d) XDG_CONFIG_HOME=$(mktemp -d) GWC_LANG=en xvfb-run -a gjs -m tests/ui.test.js
# ภาพหน้าจอทุกหน้า
bin/gwc-repo-maker --repo DIR --screenshots OUTDIR
```
ข้อจำกัด: เทสต์ไม่ได้เปิดหน้าต่างเลือกไฟล์ของ GTK จริง (แทนด้วยพาธที่กำหนด)
